# 自托管智能体上手指南

> 给运行在用户自己主机/服务器上的 agent（如各类桌面客户端、CLI agent、自托管框架）。
> 先读《新环境上手指南》通用部分，本指南只讲自托管特有的差异。

## 一、与云端环境的差异对照表

| 维度 | 云端环境 | 自托管环境 |
|---|---|---|
| 运行位置 | 云端 VM | 用户主机/服务器 |
| 网络 | 通常直连 | 可能受代理/防火墙限制 |
| 文件访问 | 经 API | 可直接读写本机文件 |
| 凭证 | 经安全通道 | 本机保管，绝不进仓库 |
| 定时任务 | 云端 cron | 本机 cron / 计划任务 |
| 风险 | 低 | 高：能动本机文件，审批规则必须先立 |

## 二、安装与基础配置

1. 确认本机 Python 3.10+ 可用（跑 `scripts/` 工具用）。
2. 配置 GitHub 访问：HTTPS + token 或 SSH，token 存本机密钥管理，不进仓库。
3. 克隆仓库到本机固定路径，路径记入 `environments/<你的env-id>.md` 登记卡。
4. 在 `registry/ENVIRONMENTS.md` 按「主机标识 + agent」查重登记（主机环境必须写具体机型 + 操作系统）。

## 三、先立审批规则（强制）

自托管 agent 能直接操作本机文件，接入第一天就必须和用户定好：

1. **删除/覆盖类操作**：哪些目录可动、哪些禁区（如系统盘、他人数据目录），写成清单。
2. **对外发送**：发消息、发邮件、调外部 API，是否需要逐次确认。
3. **凭证红线**：密码、token、验证码绝不写入仓库、不出现在日志（见 SYNC_PROTOCOL 第 6 条）。
4. 把以上三条写进你的登记卡备注，用户确认后再开工。

## 四、skill 使用

- 本库 `skills/` 的 skill 按其 SKILL.md 安装到本机。
- 需要密钥的 skill：密钥走本机环境变量或密钥文件（600 权限），不进仓库。
- 你在用的 skill 清单登记在你的登记卡里，方便其他环境知道你能干什么。

## 五、工具项目

- 本机可直接跑 `scripts/` 全套工具；建议把 `check_version.py` 接入你的写入前检查。
- 需要定时跑的任务（巡检、对账）用本机 cron，任务定义文档化后也入库一份到 `docs/`。
- 本机特有的工具脚本放你自己的 `process/<你的env-id>/` 或 `environments/<你的env-id>-persona/`，成熟通用后再提案进 `scripts/`。

## 六、测试验证

- [ ] 仓库可 pull/push，token 权限正常
- [ ] 登记卡与环境表一致，主机标识已填
- [ ] 审批规则已与用户确认并写入登记卡
- [ ] 第一笔试水写入成功并回读验证
- [ ] 定时任务（如有）试运行一次正常

## 七、踩坑 FAQ

**Q：本机代理导致 GitHub 连不上？**
A：先确认代理配置对 github.com 生效；SSH 被掐时改走 HTTPS + token。

**Q：脚本在本机跑不起来？**
A：检查 Python 版本与依赖；脚本只依赖标准库，缺依赖时看报错逐个补。

**Q：用户说"这个文件别动"，但任务需要改？**
A：停下问用户。审批规则是硬约束，不擅自扩大权限。

## 八、维护规则

- 本机工作区与远端仓库的关系：远端为准，本机是工作副本；长期不推的本机改动每周自查一次。
- 每周读 inbox 未读通告；巡检周由维护方统一跑，你配合补推遗漏。
- 换主机/重装系统时，按《新环境恢复清单》走一遍。
