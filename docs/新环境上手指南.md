# 新环境上手指南

> 给第一次接入本共享库的云端 agent 环境。按顺序走完约需 30 分钟。

## 一、数据入口与阅读顺序

按以下顺序读，不要跳：

1. `SETUP.md`（本指南的前提：占位符已替换、你已拿到 env-id）
2. `SYNC_PROTOCOL.md`（全库最高规则，重点读第 2 条写入流程、第 7 条写前握手）
3. `README.md`（按任务找入口表）
4. `INDEX.md`（摸清已有沉淀，避免重复造文档）
5. `registry/ENVIRONMENTS.md`（确认自己的 env-id 与归属）

## 二、环境构建

### 连接配置
- 确认你能访问 GitHub 仓库（读权限是底线；写权限按维护方授权）。
- 记录你的工作区本地路径，写进 `environments/<你的env-id>.md` 登记卡。

### skill 安装
- 把本库 `skills/` 下你需要的 skill 按其 SKILL.md 说明安装到本地。
- 上游 skill 只看 `skills/upstream-pointers.md` 的指针，按指针去上游安装，不复制副本入库。

### 工具跑通
- `scripts/` 的脚本需要 Python 3.10+；先跑 `check_version.py --help` 确认能执行。
- 不跑脚本也能工作（手添行补索引），但每周巡检需要维护方能跑 `build_index.py`。

## 三、接收目标与待办

1. 读 `registry/goals-master.md` 与 `registry/tracking-master.md`，找到属于你的目标。
2. 在 `registry/by-env/` 新建 `<你的env-id>-goals.md` 与 `<你的env-id>-tracking.md` 分片，把你的目标和待办写进去。
3. 总表禁止手改，只写自己的分片。

## 四、知识库使用

- 查经验：先查 `INDEX.md` 按标签找，再到 `docs/` 读原文；引用时注明出处 id（如 WL-0301）。
- 沉淀经验：用 `templates/doc-template.md` 写新文档，id 向 INDEX 查最大号顺延，推送时手添索引行。
- 过程稿放 `process/<你的env-id>/`，不污染共享区。

## 五、测试验证清单

- [ ] 能拉取远端最新并读到 INDEX.md
- [ ] 登记卡 `environments/<你的env-id>.md` 已建，env-id 与 ENVIRONMENTS.md 一致
- [ ] 两个分片已建（goals/tracking）
- [ ] 第一笔试水写入成功：小改动（如登记卡补一行）→ 带 blob SHA 提交 → 回读验证内容正常
- [ ] 会查 INDEX 取号（SYNC_PROTOCOL 第 14 条）

## 六、踩坑 FAQ

**Q：推送被拒 / 409 冲突？**
A：正常防线。停 → 拉远端最新 → 列差异 → 用户拍板 → 按 SYNC_PROTOCOL 第 4 条处理。绝不 force push。

**Q：不知道文档该放哪？**
A：查 README.md「按任务找入口」表；再拿不准问用户，不要自创顶层目录。

**Q：想改别人的文档？**
A：不直接改。写成新文档投到 `inbox/<对方env>/`，等对方或维护方处理。

**Q：INDEX.md 里找不到我刚推的文档？**
A：推送时是否手添了索引行？格式是否与表头列序一致？id 是否与 frontmatter 一致？

## 七、持久维护规则

- 事件驱动：产出重要文档当次同步入库，不攒批。
- 每次写入走 README.md「写入八步」。
- 每周读一次自己 `inbox/<你的env-id>/` 的未读通告。
- 记忆变更走 memory/README.md 的追加制；人物档案走 `memory/people/人物档案入口.md`。
