# 主题知识库构建指南

> 在本共享库体系内，从零构建一个主题知识库（如读书笔记库、投资框架库、技能手册库）的方法论。
> 本指南只讲"怎么建"，知识内容本身由你自己的环境沉淀。

## 一、总体架构（分层 + 治理线）

```
主题知识库/
├── 原文层        原文/原文摘录（大体量原文留本地，本库只放入口）
├── 提炼层        框架、概念索引、主题索引（一句话+出处回指）
├── 入口层        总索引、知识地图、更新日志（多久更新、从哪看起）
└── 治理线        与本库主协议对接：WL 取号、版本、owner、提案制
```

- 分层原则：原文与提炼分离，提炼必带出处回指，入口只放导航不放长文。
- 治理线：知识库文档同样遵守 SYNC_PROTOCOL（version、SHA 锁、禁强推）。

## 二、构建环境

- 构建环境 = 负责该知识库的 env-id，在文档 frontmatter 的 source_env 标明。
- 建议由一个环境主建（owner），其他环境用提案制贡献，避免多头写分叉。

## 三、工具链按规模分档

| 规模 | 原文量 | 工具链 |
|---|---|---|
| 小 | < 50 篇 | 手工提炼 + INDEX 手添行 |
| 中 | 50–500 篇 | 脚本辅助（抓取/转 md/建索引）+ `scripts/check_duplicates.py` 对账 |
| 大 | > 500 篇 | 分卷存放 + 增量同步脚本 + 定期 dedupe + 月度盘点 |

工具脚本先放 `process/<env>/` 验证，成熟通用后提案进 `scripts/`。

## 四、方法流程

### 分层命名
- 目录：`docs/<主题slug>/`；索引文件命名固定：`总索引.md`、`知识地图.md`、`更新日志.md`。
- 主题 slug 全库唯一，建之前在 INDEX.md 查重。

### 受控标签
- 新标签先登记到 `taxonomy.md` 的 topic/* 区，再使用。
- 标签示例：study / work / finance / health / social / ai-news（按需扩充）。

### 入库 SOP
1. 原件先原样保存（本地或 `process/<env>/`），再归类。
2. 写提炼文档：框架 + 概念索引，一句话一条，必带出处回指。
3. 分配 WL id（现读远端 INDEX 取最大号+1），补 frontmatter。
4. 推送 + 手添 INDEX 行 + 回读验证 + 汇报。

### 提炼方法
- 一条提炼 = 一个观点 + 出处回指 + 置信度（如有推断）。
- 不复制大段原文；原文只存指针（本地路径或链接）。
- 定期把"入口层"重读一遍，删过时、并重复、补缺口。

### 去重
- 入库前在 INDEX.md 按标题/主题查重。
- 周期跑 `scripts/check_duplicates.py`，冲突组停下报用户，不自动合并。

## 五、消费方规则

- 其他环境使用知识库：只读 + 引用注明 WL id。
- 发现错误/缺口：走 inbox 给 owner 环境提案，不直接改。
- 引用时转述结论，不整段复制原文（尤其对外分享时先脱敏）。

## 六、长期维护机制

- 更新日志：每次增量更新记一行（日期 · env-id · 新增/修订摘要）。
- 每周巡检：owner 检查入口层是否跟上提炼层（索引覆盖率）。
- 每月盘点：失效链接、过时提炼、标签词表、体积。
- 归档：主题完结后 status 标 archived，文件保留，入口注明完结日期。
