# 新环境恢复清单

> 换主机、重装系统、云端环境重建后，按本清单把工作环境恢复到可用状态。
> 原则：远端仓库为准，本机/新环境是工作副本；凭证类只能人工录入，绝不从仓库"恢复"。

## 一、拉仓库

- [ ] 克隆仓库到本机固定路径（与登记卡记录的路径一致）。
- [ ] 确认能 pull/push，远端 HEAD 与本地一致。

## 二、恢复记忆与口径（只读顺序）

按顺序读，不要跳：
1. `SYNC_PROTOCOL.md`（重温最高规则）
2. `README.md`（入口表）
3. `memory/MEMORY.md` + `memory/USER.md`（用户记忆与偏好）
4. `memory/people/`（人物档案：先读对象档案索引，再按需读单个对象）
5. `registry/ENVIRONMENTS.md`（确认自己的 env-id 还在表上；新主机=新 env-id，按身份延续规则登记）

## 三、重建定时任务

- [ ] 列出原环境的所有定时任务（查 process/<原env>/ 或任务定义文档）。
- [ ] 在新环境逐个重建：触发条件、执行内容、归属目标。
- [ ] 每个任务试运行一次，确认读写路径正确。

## 四、按指针重装程序与 skill

- [ ] 按 `skills/upstream-pointers.md` 的指针重装上游 skill。
- [ ] 按登记卡/过程文档重装本机工具（脚本、CLI）。
- [ ] 跑一遍 `scripts/check_version.py` 确认工具链正常。

## 五、凭证重新录入（只能人工）

- [ ] 各平台的 token/key/密码：用户人工重新录入本机密钥管理。
- [ ] 验证每个凭证可用（如调一次只读接口）。
- [ ] 确认仓库里没有凭证残留（grep 自查）。

## 六、设备与连接重配

- [ ] 代理/网络：确认 github.com 可达。
- [ ] 已配对设备（如手机、平板）：重新配对并验证收发正常。
- [ ] 通知通道：确认推送能到达用户。

## 七、恢复验收打勾表

- [ ] 一至六全部完成
- [ ] 第一笔试水写入成功并回读验证
- [ ] 定时任务试运行正常
- [ ] 向用户汇报：恢复完成 + 试水提交号
- [ ] 在 `registry/ENVIRONMENTS.md` 更新该环境的登记行（如主机变更）
