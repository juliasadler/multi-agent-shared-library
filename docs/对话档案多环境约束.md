# 对话档案多环境约束

> 对话档案 = 某个主题/任务的多轮对话沉淀。多环境同时归档时，必须遵守本约束，否则档案会分叉、重号、互相覆盖。

## 一、档案与正本的区分

| 类型 | 是什么 | 放哪 | 谁能写 |
|---|---|---|---|
| 正本 | 提炼后的结论、手册、记忆条目 | docs/、memory/ | owner/维护方 |
| 对话档案 | 对话过程的原始记录（问答流水、中间稿） | process/<env>/ 或 docs/archive/ | 归档的环境自己 |

对话档案是证据副本，永远不覆盖正本（见 SYNC_PROTOCOL「最新判定」权威层级）。

## 二、命名规范（强制）

- 目录：`process/<env-id>/<主题slug>/`，主题 slug 全库唯一，建之前先在 INDEX.md 查重。
- 文件：`YYYY-MM-DD-主题.md`；续篇加 `-02` 后缀，不改旧文件名。
- person/对象相关档案另遵守《人物档案协议》的三件套结构。

## 三、元数据头（强制）

每份归档文档必须带 frontmatter：

```yaml
---
title: <档案标题>
id: WL-xxxx            # 取号规则见 SYNC_PROTOCOL 第 14 条
type: log
source_env: <你的env-id>
source_agent: <agent 名>
origin: <原对话/任务出处>
created_at: YYYY-MM-DD
updated_at: YYYY-MM-DD
timezone: Asia/Shanghai
version: 1
tags: [log]
status: active
visibility: private
---
```

## 四、内容铁律

1. 只归档事实与过程，不归档凭证（密码/token/验证码出现即删）。
2. 引用他人对话内容先脱敏（去称呼、人名、账号、路径）。
3. 一份档案只讲一个主题；跨主题拆文件，不塞大杂烩。
4. 归档时标注「归档自哪次对话、对话时间」，方便溯源。

## 五、各环境上传五步流程

1. 本地整理：脱敏 → 补 frontmatter → 取 WL 号（现读远端 INDEX，最大号+1）。
2. 定位置：`process/<自己env>/` 当期主题目录；确定要进共享区的才放 `docs/`。
3. 推送：小批量提交，提交信息带 env-id 与主题。
4. 索引：同提交手添 INDEX.md 行。
5. 回读验证 + 向用户汇报。

## 六、读取方 / 生成方维护方法

- **生成方**（归档的环境）：对自己档案的后续补充用 version+1 增量写；档案定稿后 status 标 active，不再频繁改。
- **读取方**（其他环境）：只读；发现档案过时/有误→走 inbox 给生成方提案，不直接改。
- 档案被正本吸收后（如提炼成手册进了 docs/），在档案头加一行「已提炼为 WL-xxxx」， status 标 superseded，文件保留。

## 七、多运行端并行归档规则

同一 env-id 的多个运行端同时归档时：

1. 各端先写自己本机，推送前必须刚拉取远端。
2. 同一主题只由一端归档，另一端发现重复时停下，先对账。
3. 推送后在主题目录留一行注记：时间 · 端点自述 · 归档了什么。
4. 冲突按 SYNC_PROTOCOL 第 4 条：停 → 列差异 → 用户拍板。
