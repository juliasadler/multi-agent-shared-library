# 数据使用指南

> 本库是多环境共享的"活"库：读之前先同步，用之前先验新，写之前先确权。

## 一、先同步再使用

任何任务开始前：拉远端最新 → 读自己 `inbox/<你的env-id>/` 未读通告 → 再读/写。
拿过期副本做判断，是本库最常见的事故源头。

## 二、判断是不是最新

- **文档级**：看 frontmatter 的 `version` 与 `updated_at`；写入前必须与远端比对，小了就是旧副本，停写。
- **条目级**：记忆条目行尾标记 〔YYYY-MM-DD·环境ID〕，一眼看出何时谁记的。
- **索引级**：INDEX.md 是脚本/手添行维护的，可能滞后；拿不准时以文档 frontmatter 为准。
- **总表级**：registry 总表是聚合生成物，看更新时间；要最新状态直接看各环境分片。

## 三、使用权限速查

| 区域 | 读 | 写 | 说明 |
|---|---|---|---|
| docs/（他人文档） | ✅ | ❌ | 想改→投 inbox/<对方env>/ |
| docs/（自己文档） | ✅ | ✅ | version+1，带 SHA 写 |
| memory/ 正本 | ✅ | 仅维护方 | 他人走 proposals 提案 |
| memory/people/ | ✅ | 仅维护方 | 他人走 proposals 提案 |
| registry 总表 | ✅ | ❌ | 脚本聚合，禁手改 |
| registry/by-env/自己分片 | ✅ | ✅ | 只写自己的 |
| process/<自己env>/ | ✅ | ✅ | 只写自己目录 |
| process/<他人env>/ | ✅ | ❌ | 接手时建续作，不改原文件 |
| environments/自己 | ✅ | ✅ | 登记卡+人格目录 |
| inbox/自己 | ✅ | 改 status | 只改自己通告的已读状态 |
| INDEX.md | ✅ | 手添行 | 不改他人行、不删行 |

## 四、引用规范

- 引用库内文档注明出处 id（如 WL-0301），方便溯源。
- 引用外部资料注明来源链接与获取日期。
- 转述给用户看的内容：去掉内部黑话，只讲结论与依据。

## 五、典型场景

**场景 1：查一份经验怎么做**
INDEX.md 按标签找 → docs/ 读原文 → 按引用规范用。

**场景 2：接手别人的任务**
registry 总表看状态 → process/<对方env>/ 读过程稿 → 在自己目录建续作 → 更新自己分片。

**场景 3：给记忆补一条**
先确认你是维护方；不是→写 proposals 提案。是→按追加制增量写，CHANGELOG 记一行。

**场景 4：两个环境说法不一致**
停 → 按 SYNC_PROTOCOL「最新判定」比（总表>正本>快照；version→updated_at）→ 列差异报用户拍板。

## 六、红线

- 绝不整文件覆盖、绝不 force push。
- 密码、密钥、token、验证码永不入库。
- 不确定就停下来问用户，不猜、不删、不覆盖。
- 记忆与人物档案含隐私，只在私有仓内流转，绝不外发。
