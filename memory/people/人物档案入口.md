# 人物档案入口（日常使用与更新说明）

> 本文件是人物档案的**日常操作手册**：任何环境打开这一份，就能知道人物档案在哪、怎么读、怎么更新、怎么写提案。
> 冲突处理与防覆盖以 SYNC_PROTOCOL.md（WL-0001）为最高规则；字段与结构细则见《人物档案协议》（WL-3022）；本文件与 WL-3022 冲突时以 WL-3022 为准。文中人名均为虚构示例。

## 一、先看这里（30 秒定位）
- 想知道「有哪些对象、进展到哪了」→ 对象档案索引.md（WL-3021），一人一行。
- 想接手某个对象继续分析 → 打开 `memory/people/<person-id>/` 三件套：档案.md（快照）、事件流水.txt（最近事件）、analysis/（历史长分析）。
- 记不清规则 → 本文件第三节（读取）与第四节（更新）；细则查 WL-3022。

## 二、档案长什么样（一人一目录）
```
memory/people/<person-id>/
├── 档案.md          快照（阶段/评分/未决事项）+ Hypotheses + 关系现状
├── 事件流水.txt      一行一条 JSON，只追加，永不改旧行
└── analysis/        每轮长分析一篇，只进不出，结尾带回写清单
```
另有 `memory/people/<中文名>.md` 事实页存人物事实（Facts 正本，如 `张三.md`）。一件事只有一个正本：阶段/评分在档案.md，事件在事件流水，推断在档案.md 的 Hypotheses，长分析在 analysis/。

## 三、日常读取（接手分析时照做）
1. 对象档案索引.md（WL-3021）确认对象与进度。
2. 读该对象 档案.md 快照 + 事件流水.txt 最近 5–8 条；核对快照「快照更新至事件」等于流水最后一条 id，不一致=档案过期，先补齐再分析。
3. 需要证据时按快照/流水里的 ref 打开 analysis/ 对应篇。
4. 一次只读当前一个对象；跨对象比较只能并排两份快照，禁止串读、禁止把甲的事实写进乙的目录。

## 四、日常更新（两种身份，两种写法）
### A. 你是维护方
每轮分析结束，当次完成回写闭环，缺一不可：
1. 事件流水.txt 末尾追加新事件行（id 递增；评分/阶段变化配一条说明依据）。
2. 更新 档案.md 快照与 Hypotheses（推断必带 confidence 与证据回指）。
3. analysis/ 新开一篇存本轮分析，结尾写回写清单。
4. 刷新 对象档案索引.md（WL-3021）该对象一行。
5. 按 SYNC_PROTOCOL 写入八步提交：拉远端→验版本→带 blob SHA 写→回读验证→向用户汇报（文件、版本、提交）。

### B. 你不是维护方
- 正本文件只读，**绝不直接改** memory/people/ 下的档案与事实页。
- 本轮有新结论：新建提案 `memory/proposals/提案-<你的env>-<YYYYMMDD>-<序号>.md`，写清：对象、新增/修正的事实或推断、出处、建议回写到哪个文件哪一节。
- 推送后向用户说明交了哪份提案；由维护方审后并入正本，提案保留归档。

## 五、新建对象
1. 在对象档案索引.md（WL-3021）加行并分配 person-id（稳定英文 slug，永不改名）。
2. 建 `memory/people/<person-id>/` 三件套，按 WL-3022 模板。
3. 有事实需求时建 `<中文名>.md` 事实页并在 people/INDEX.md 登记。
4. 首轮分析完成后按第四节回写。

## 六、失效、归档与删除
- 事实/推断被推翻：不删原文，标 superseded 注明被谁取代与失效日期，移入档案.md 的 Archive 节。
- 事件写错：追加一条 type=retract 的行指向上一个 id，不改旧行。
- 活跃度归档：长期无实质互动/提及 → `activity=dormant`（逻辑归档，文件不移动、不更名）；重新出现实质互动 → 自动唤醒回 `active`。归档由用户拍板，任何环境不得自行归档。
- 对象级彻底删除须经用户单独确认（git 历史可能留旧版本，彻底清除需重写历史、不可逆），不得默认执行。

## 七、红线速记
- 禁止整文件覆盖、禁止 force push；version/SHA 对不上即停、列差异、请用户拍板。
- 密码、token、验证码等秘密永不进档案。
- 分析结论未回写三件套 = 本轮未完成；回写清单缺项不得交付。
