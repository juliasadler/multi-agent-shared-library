# 人物档案协议（多环境统一维护规则）

> 本协议管「人物/对象档案」在多环境间的存放、读取、更新与防覆盖。同步纪律（版本校验、提交带锁、禁止强推）以 SYNC_PROTOCOL.md（WL-0001）为最高准绳，本协议只补人物档案专属规则。接手入口：对象档案索引.md（WL-3021）；日常操作手册：人物档案入口.md（WL-3024）。文中人名均为虚构示例。

## 一、必读清单
- SYNC_PROTOCOL.md（写前验版本、提交带锁、禁止强推，否则旧版会盖掉新版）。
- memory/README.md（memory 区单写者与提案制）。
- UNIVERSAL_PROMPT.md（跨 agent 通告协作口径）。
新环境第一次写入前仍须执行 SYNC_PROTOCOL 的「写前握手」。

## 二、目录与三件套（一人一目录，只进不出）
```
memory/people/<person-id>/
├── 档案.md          快照 + Hypotheses + 关系现状（唯一正本）
├── 事件流水.txt      一行一条 JSON，只追加，永不改已写行
└── analysis/        每轮长分析一篇 YYYY-MM-DD-主题.md，只进不出，结尾必带回写清单
```
- person-id 为稳定英文 slug，永不改名；显示名变更只改档案.md 显示名。
- 人物事实页（`memory/people/<中文名>.md`，如 `张三.md`）为 Facts 层正本，与三件套并存：Facts 只在事实页维护，档案.md 不复制全量事实、只回指。文件名命名规范见 SYNC_PROTOCOL.md 第 12 条（一律中文名，用户名/ID 类保留原样）。

## 三、字段所有权（一件事只有一个正本）
| 信息 | 唯一正本 | 其他层 |
|---|---|---|
| 阶段、评分、未决事项 | 档案.md 快照 | 入口索引只镜像展示，分析篇禁止改分 |
| 事件 | 事件流水.txt | 快照的「最近动态」由流水末 N 条生成，不手写 |
| 推断/假设 | 档案.md Hypotheses（必带 confidence 与证据回指） | 分析篇的推论必须回写至此才生效 |
| 长分析与聊天原文 | analysis/ 篇 | 只被 Facts/Hypotheses 回指引用 |
| 人物事实 | 人物事实页 `<中文名>.md` | 档案.md 只回指、不复制 |

## 四、读取（渐进披露，单对象）
1. 先看对象档案索引（WL-3021）确认对象与进度。
2. 调该对象快照：档案.md（阶段/评分/未决事项 + 活跃 Facts 摘要 + 最近 5–8 条事件 + confidence≥0.4 的推断），控制在约 4000 字内。
3. 需要时间线读事件流水近 30 条；需要证据按回指打开 analysis/ 对应篇。
4. **硬隔离**：一次召回只准当前 person-id；跨对象比较只能并排两份快照，禁止把甲的事实写进乙的目录。

## 五、更新（回写闭环，缺一不可）
每轮分析结束，按序回写：
1. 事件流水.txt 末尾 append 新事件行（id 递增；评分/阶段变更必须配一条说明依据）。
2. 更新 档案.md 快照（阶段/评分/未决事项/快照更新至事件）与 Hypotheses（新增或失效标注）。
3. analysis/ 新开一篇存本轮分析，结尾写《回写清单》逐条标明回写到了哪。
4. 刷新 对象档案索引（WL-3021）该行（阶段/评分/最近分析/进展一句话）。
5. 自检：快照「更新至事件」== 流水最后一条 id；不一致即过期，先补齐再交付。
无回写清单的分析视为未完成，不进入后续快照。

## 六、防覆盖（与 SYNC_PROTOCOL 的对应关系）
- 单写者：memory/ 人物档案正本只由登记维护方写；其他环境一律只读 + 向 memory/proposals/ 投提案，维护方审后增量并入。
- 写前验版本：动手前拉远端，本地基线 version 与远端不一致即停、列差异、用户拍板（SYNC_PROTOCOL 第 2 步，有校验脚本 scripts/check_version.py）。
- 提交带锁：GitHub API 更新必须带当前 blob SHA；git 推送被拒禁止 force push。
- 历史可恢复：每轮一次提交、提交信息带 person-id；误覆盖按 SYNC_PROTOCOL 第 9 节恢复手册处理（冻结→定位完好版本→恢复并 version+1→留痕）。
- 新鲜度校验（防读旧快照）：档案.md 快照必带「快照更新至事件」标记；接手时先核流水末条，对不上先补齐（见五-5）。

## 七、失效、归档与删除
- 事实/推断被推翻：不删原文，标 superseded 并注明被哪条取代、失效日期，移入档案.md 的 Archive 节（失效不删除，保证可复盘）。
- 事件写错：append 一条 type=retract 的行指向上一个 id，不改已写行。
- 活跃度归档：人物活跃度管理见本目录《人物档案活跃度机制》（模板未内置，按需补充）。建议：长期无实质互动/提及 → `activity=dormant`（逻辑归档，文件不移动、不更名，退出默认上下文、显式可达）；重新出现实质互动 → 自动唤醒回 `active`。归档由用户拍板，任何环境不得自行归档。
- 对象级删除（用户明确要求时）：二次确认后删目录并重建索引；必须如实告知：git 历史仍可能留有旧版本，彻底清除需重写 git 历史、不可逆，须用户单独确认、不得默认执行。
- 整理节奏：写入时轻整理（去重、失效检查）；每对象事件累计超 50 条或每月做一次深整理，产出整理报告经用户确认后才落盘；整理永不自动硬删。

## 八、新对象建档
1. 在对象档案索引（WL-3021）加行、分配 person-id。
2. 建 `memory/people/<person-id>/` 三件套（档案.md 按模板：快照 / Facts 回指 / Hypotheses / 关系现状 / Archive 五节）。
3. 有人物事实需求时同步建 `<中文名>.md` 事实页（如 `张三.md`）并在 people/INDEX.md 登记。
4. 首轮分析完成后按第五节回写。

## 九、数字说明（诚实边界）
本协议中的 4000 字快照、最近 5–8 条事件、50 条深整理等阈值均为设计提议，无针对个人关系档案的实证最优值；按实际对象数量与使用感受调整，调整时升版记录。
