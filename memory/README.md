# 记忆与人格区说明（memory/ 与 environments/）

## 为什么分开放

- **用户记忆（memory/）是全库共享的唯一权威**：MEMORY.md、USER.md、people/ 人物档案。不管哪个 agent 服务用户，读的都是同一份，避免"每个环境各记一本账"。此区单写者制：默认由维护方（登记为 maintainer 的环境）维护，其他环境只读引用，新发现走 memory/proposals/ 以提案形式投递，经确认后由维护方合并。
- **人格（environments/<env>/）按环境隔离**：各 agent 自己的人设与操作手册天然属于各环境，不强行统一。各 agent 接入时建自己的目录，不要改别人的。

## 敏感度

- 本区为 private 级：含用户与人物档案，仅在私有仓内流转，绝不外发、绝不进公开仓。
- 密码、token、验证码等秘密一律不进本库（走保险库）。记忆文件里若出现联系方式等信息，仅限本私仓共享，不得复制到其他仓。

## 同步规则

- 本区文件更新走标准流程：拉取→验 version→改→version+1→重建索引→提交→回读。
- MEMORY.md 体量会长大，超过 200KB 后按年份拆 MEMORY-YYYY.md，本文件保留索引头。

## 记忆追加制细则（防覆盖核心条款）

记忆文件最大的风险是「拿旧副本整文件替换新版」。本库用四条硬规则防住：

1. **单写者**：memory/ 区只有登记的维护方能改 MEMORY.md / USER.md / people/。其他环境对记忆只有读权限和提案权，永远不直接编辑这三个文件。
2. **提案制（其他环境追加记忆的唯一通道）**：在 memory/proposals/ 下新建 `提案-<env>-<YYYYMMDD>-<序号>.md`（只新建、从不改别人提案），写清新增/修正的事实与出处；维护方定期审阅，确认后以增量补丁方式并入正本，提案文件保留归档。
3. **增量补丁、禁止整覆**：正本修改只能是定位到具体条目的增补/修订（加条目、改某条、删某条须注明依据），提交前必须基于刚拉取的最新版；拿本地旧副本整文件 PUT 一律视为违规写入。
4. **乐观锁 + 可回滚**：写入必须带当前 blob SHA，副本过期会被 GitHub 拒绝（409）；万一误操作，git 历史保留每一版，可按提交恢复。

判定标准：任何一次记忆变更，提交 diff 里应当只出现预期条目的增删行；若整文件大面积变动，即视为异常，停下复核。

## 新鲜度判定与条目标记

- **文档级**：每份记忆文件头部 frontmatter 带 updated_at（日期）、source_env（来源环境）、version（整数）。写入前必须拉取远端比对：本地基线 version 或 SHA 小于远端即为旧副本，停写。
- **条目级**：新追加的记忆条目行尾加标记 〔YYYY-MM-DD·环境ID〕，一眼区分何时、哪个环境记下的；旧条目不回溯补标，以变更日志为准。
- **日志级**：每次变更在 memory/CHANGELOG.md 追加一行，与正本 version 对应；日志只增不改。

## 本机资源指针索引

- 各环境 skill / 记忆库 / 插件的本机路径，可在 `process/<env>/local-resource-index.md` 登记：只登记路径、不存副本。
- 各环境可自持记忆正本的派生摘要（仅本机、不入库不外发），但摘要与正本冲突时以正本为准。

## 环境自治项（不作跨环境统一、不列冲突）
以下内容按环境各自定义，各环境互不统一，任何 agent 不得将其列为冲突上报或要求他方更正：
- **记忆暗号**：每个环境的暗号独立有效，发现不同暗号时自动忽略，不入库、不对账、不上报。
- 各环境自记的语气口径、本机路径细节等环境事实：以各自登记卡为准，不要求与共享正本措辞一致。
判定冲突时先排除本节自治项，再按 SYNC_PROTOCOL 冲突处理流程走。
